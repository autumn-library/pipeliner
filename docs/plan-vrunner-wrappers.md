# План: приведение обёрток vrunner в `Скрипты.os` к vanessa-runner 3.0

## Контекст

Документация: https://autumn-library.github.io/vanessa-runner/ (рендер) и
https://github.com/vanessa-opensource/vanessa-runner (исходники `docs/product`).

vanessa-runner 3.0 несовместим с 2.x:

- команды стали **иерархическими**: `vrunner xunit` → `vrunner test xunit`,
  `vrunner run` → `vrunner run enterprise`, `vrunner syntax-check` → `vrunner validate syntax-check`;
- опции указываются **до позиционного аргумента**;
- файл настроек `vrunner.json` → `autumn-properties.json`, переменные `RUNNER_*` → `VRUNNER_*`.

Текущий модуль `src/Модули/Скрипты.os` — это «фабрика команд»: каждая функция
возвращает строку для `Задача.Скрипты.Добавить(...)`. Часть обёрток написана под
2.x, часть — прямые вызовы `1cedtcli` и `ibcmd`, которые в 3.0 уже абстрагируются
vrunner'ом.

Текущий шаблон функции (обязательные параметры → необязательные со значением по
умолчанию, документирующий комментарий с расшифровкой команды):

```bsl
// vrunner infobase init [--ibcmd] --ibconnection <СтрокаПодключения>
//
// Параметры:
//   СтрокаПодключения - Строка - Например: /Fbuild/ib
//   ИспользоватьИбкмд - Булево - Флаг --ibcmd
//
//  Возвращаемое значение:
//   Строка -
//
Функция СозданиеБазы(СтрокаПодключения, ИспользоватьИбкмд = Истина) Экспорт
	Шаблон = "vrunner infobase init %1 --ibconnection %2";
	Возврат СтрШаблон(Шаблон,
		?(ИспользоватьИбкмд, "--ibcmd", ""),
		СтрокаПодключения);
КонецФункции
```

| 9 | `ЗапускТестовЯксЮнит` | `vrunner run enterprise [--ibsrv] --ibconnection --command "RunUnitTests=<файл>"` | ❌ | в 3.0 — отдельная команда `test yaxunit` | `test yaxunit --ibconnection [--yaxunit-config <файл> | --ext/--report-path]` |
| 10 | `ЗапускТестовВА` | `vrunner run enterprise [--ibsrv] --additional /testmanager --ibconnection --execute "<epf>" --command "StartFeaturePlayer;…"` | ❌ | в 3.0 — отдельная команда `test vanessa` | `test vanessa --ibconnection --vanessasettings --bddrunner-path --workspace [--feature-path]` |
| 11 | `КонвертацияЕДТВКонфигуратор` | `1cedtcli -data … export --project …` | ❌ | прямой `1cedtcli`; в 3.0 — `cf convert` (опции `--edt-*`) | `cf convert -s <edt> <out>` |
| 12 | `ИмпортПроектаЕДТ` | `1cedtcli -data … import --project …` | ❌ | прямой `1cedtcli`; импорт в vrunner автоматический | отдельной команды нет → удалить |
| 13 | `ВалидацияЕДТПоСпискуПроектов` | `1cedtcli validate --project-name-list [...]` | ❌ | прямой `1cedtcli`; «списка проектов» в 3.0 нет | `validate edt --src <проект>` (по проекту) |
| 14 | `ВалидацияЕДТПоСпискуКаталоговПроектов` | `1cedtcli validate --project-list [...]` | ❌ | прямой `1cedtcli` | `validate edt --src <проект>` |

Не относятся к vrunner, оставляем без изменений: `ГенерацияОСкриптЛинукс`,
`ВыполнитьОСкрипт`, `ЛогЭхоЛинукс`.

### Ключевой дефект именования

Параметр `ИспользоватьАвтономныйСервер` в разных функциях означает **разные**
флаги:

- в 1, 2, 3, 4, 5, 7 → `--ibcmd` (утилита ibcmd вместо Конфигуратора) — **неверное имя**;
- в 8, 9, 10 → `--ibsrv` (автономный сервер ibsrv) — имя корректное.

Предложение: завести два разных параметра —
`ИспользоватьИбкмд` (→ `--ibcmd`) и `ИспользоватьАвтономныйСервер` (→ `--ibsrv`).

## 3. План реализации

### 3.1. Соглашения (шаблон)

1. Имя функции — русское действие. Обязательные параметры в начале, необязательные
   со значением по умолчанию в конце.
2. Документирующий комментарий: первая строка — расшифровка оборачиваемой команды
   `vrunner <группа> <подкоманда> [опции] <аргумент>`, затем `Параметры:` (имя, тип,
   пример) и `Возвращаемое значение:`.
3. Булевы флаги реализуются через `?(Флаг, "--флаг", "")`.
4. Булевы флаги-опции с двумя состояниями (`--active`, `--safe-mode`,
   `--unsafe-action-protection`, `--main-roles-for-all`) принимают `Булево` и
   формируют `--флаг true/false` (по спецификации `set-options`).
5. Повторяемые опции (`--ext`, `--mode`, `--target`, `--report-format`, `--coverage-ext`,
   `--filter-app`, `--filter-name`, `--role`, `--edt-vmargs`) принимают `Массив из Строка`
   и разворачиваются в повторяющиеся флаги.

### 3.2. Общие параметры подключения

Чтобы не дублировать, обёртки принимают следующие необязательные параметры в конце
(где применимо): `ИспользоватьИбкмд`, `Пользователь`, `Пароль`, `ВерсияПлатформы`,
`КодРазрешения`, `РежимРеструктуризации`, `ДинамическоеОбновление` и т.п. Точный набор
указан для каждой функции.

### 3.3. Фазы

- **Фаза 0. Исправить существующие** (10 функций + 1 удаление): переименовать параметр
  `ИспользоватьАвтономныйСервер` → `ИспользоватьИбкмд` там, где это `--ibcmd`;
  исправить тела 2, 3, 9, 10, 6, 11; удалить `ИмпортПроектаЕДТ`; переписать 13/14 в
  одну `ВалидацияЕДТ`.
- **Фаза 1. Ядро CI**: `cf` + `cfe` + `epf` (compile/decompile/load/unload/convert).
- **Фаза 2. infobase**: dump-dt, restore-dt, create-user, lock-resources,
  scheduled-job, extensions.
- **Фаза 3. Тесты и проверки**: `test xunit`, `validate syntax-check`, `run designer`.
- **Фаза 4. Тесты модуля** (`tests/Скрипты.os`) и обновление `docs/api/Скрипты.md`.

> `repo` и `cluster` — отложены (не в этой итерации).

### 3.5. Что сделать с прямыми вызовами 1cedtcli/ibcmd

- `КонвертацияЕДТВКонфигуратор` → заменить на `cf convert` (убрать `-data`/`--project`,
  опции EDT переносятся в `--edt-*`).
- `ИмпортПроектаЕДТ` → удалить (в vrunner импорт EDT автоматический; при необходимости
  управляется `--edt-workspace`, `--edt-path`, `--edt-version`).
- `ВалидацияЕДТПоСпискуПроектов` / `ВалидацияЕДТПоСпискуКаталоговПроектов` →
  заменить на `validate edt` (валидация по одному проекту за вызов; список — это цикл
  на стороне вызывающего кода).
- `НастройкаФлаговРасширения` → заменить на `infobase extensions set-options`.

### 3.6. Тесты

Создать `tests/Скрипты.os` по образцу `tests/ДействияОкружения.os`: для каждой функции —
проверка, что возвращаемая строка равна ожидаемой команде (с `--ibcmd` и без, с
опциональными параметрами и без них).

## Принятые решения

1. **Имена функций** — сохраняем (обратная совместимость), правим только тела и имя
   параметра `ИспользоватьАвтономныйСервер` → `ИспользоватьИбкмд` там, где это `--ibcmd`.
2. **Объём** — только CI-ядро: `cf`, `cfe`, `epf`, `infobase`, `run`, `test`, `validate`.
   `repo` и `cluster` — **отложены** (не в этой итерации).
3. **Прямые 1cedtcli/ibcmd** — заменяем на vrunner:
   `КонвертацияЕДТВКонфигуратор` → `cf convert`,
   `НастройкаФлаговРасширения` → `infobase extensions set-options`,
   `ИмпортПроектаЕДТ` → удаляем (импорт EDT в vrunner автоматический),
   `ВалидацияЕДТПоСписку*` → `validate edt` (списка в 3.0 нет — одна функция `ВалидацияЕДТ`).

> Исключение из п.1: `ВалидацияЕДТПоСпискуПроектов` и
> `ВалидацияЕДТПоСпискуКаталоговПроектов` объединяются в одну `ВалидацияЕДТ`, т.к.
> концепция «списка проектов» в 3.0 отсутствует; `ИмпортПроектаЕДТ` удаляется.

4. **`СозданиеБазы` (`infobase init`)** — расширена необязательными параметрами
   `ИсточникКонфигурации` (`--src`), `Расширения` (`--ext`, повторяемая),
   `Рекурсивно` (`--recursive`) и набором опций EDT (`КаталогВоркспейсаЕДТ`,
   `ФорматИсходников`, `ПутьКЕДТ`, `ВерсияЕДТ`, `ТаймаутЕДТВСек`, `ПамятьВГБ`):
   `init` умеет за один вызов создать базу, загрузить конфигурацию и расширения
   и обновить БД. Набор опций EDT вынесен в приватный помощник `ОпцииЕДТ(...)`.
